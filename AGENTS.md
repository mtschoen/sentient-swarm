# Agent instructions

## Global constraints (binding)

- Plain JavaScript ES modules and WGSL. No TypeScript. No runtime dependencies. Vite and Playwright are dev dependencies only.
- Shaders are loaded with `fetch(new URL('./shaders/<name>.wgsl', import.meta.url))` so the page also runs from any static server without Vite.
- Full-word identifiers (`maximum`, not `max`; `position`, not `pos`) in JavaScript. WGSL may use `vec2f` style built-in names but user identifiers follow the same rule.
- No em-dashes (U+2014) anywhere, including comments and docs.
- Every source file under about 500 lines, or carrying a one-line note at the top saying why.
- No hard-coded machine paths. No wall-clock assertions in tests; inject time.
- Mobile WebGPU limits are designed for: at most 8 storage buffers bound per shader stage; agent data interleaved in 16-byte aligned structs with no `vec3` in storage layouts; `@workgroup_size` at most 256; workgroup memory at most 16 KB; timestamp queries optional.
- Neighbor contributions are averaged, never summed. Per-agent fine-pass neighbor sampling is capped at `MAXIMUM_NEIGHBOR_SAMPLES = 32`.
- The world is 16 by 9 world units. The playable arena is the largest rectangle of the window's aspect centered in it (`arenaBoundsForAspect` in `src/sim/layout.js`, carried by `Viewport.arenaBounds`, `Game.setArenaBounds` and `Simulation.setArenaBounds`), mapped to the whole canvas so the game fills the window at any aspect between 1:4 and 4:1 (letterboxed beyond that). The coarse field and grid still cover the whole world; the spawn pressure target scales with the arena's area fraction so density is what stays constant. Renderer works in device pixels.
- Species count is 5. Coarse field is 64 by 36 cells with 8 float channels (5 species densities, 1 threat, 2 padding). Shipped shares are 0.9 Chaser, 0.03 Orbiter, 0.02 Skittish, 0 Lattice, 0.05 Predator (`DEFAULT_SHARES`, owner ruling R38); the lab's `equalFive` mix restores equal shares.
- Commit after every task with a message in the imperative; end commit messages with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Commands

- `npm run dev`: dev server on 127.0.0.1:5174 (strictPort).
- `npm run build`: static build into `dist/`, base taken from `PAGES_BASE` (default `/`).
- `npm test`: CPU logic tests via node:test.
- `npm run smoke`: Playwright browser smoke test.
- `npm run coverage`: `node --test` with Node's built-in coverage over `src/**/*.js` (no dependency), failing under the line and function floors in `package.json` (92 and 86); `src/sim/grid.js` and `src/render/render-shaders.js` are excluded by exact path (GPU-only modules; `tests/coverage.test.js` rejects wildcards and stale paths).
- `npm run check:gpu`: `tests/browser/gpu-checks.mjs` runs the small GPU page checks in sequence (`webgpu-probe`, `grid`, `player`, `simulation`, `projectiles`, `bloom`); exit 2 means the probe found no adapter. `WEBGPU_ADAPTER=fallback` forces the software adapter (test side only, never the default). CI: `.github/workflows/check.yml` runs `npm test`, `npm run coverage` and `npm run build` on every push and pull request, plus a required software-GPU `npm run check:gpu` job; `browser.yml` runs the browser suite on a self-hosted GPU runner (main pushes and manual dispatch only); `tests/workflows.test.js` checks the workflow files by fixed spelling.

## Audio and probe rules

- Audio: notes are scheduled at least 100 ms ahead against `AudioContext.currentTime` through `StepSequencer` (lookahead 0.1 s, a timer only advances the schedule); never `setTimeout`-driven notes. The gesture that starts the run is the single unlock (`audio.unlock()` inside the event handler; a gamepad press is not an activation). Music tempo is 124 to 134 bpm, changed on bar starts only. Tests fake the audio context and inject time.
- Probe contract: the frame-time probe (`FrameTimeProbe` through `QualityController`) runs during Playing only (`Game.acceptsProbeFrames`), target 10 ms, at most one step per 3 s; it steps down particles, then bloom, then capacity (a preset down). `?probe=off` or `?capacity=` disables it; every browser check passes `probe=off`. Presets change counts and budgets only, never gameplay.

## Pass order

Each animation frame `FrameLoop` runs zero or more fixed update steps, then one render. Each is its own queue submission.

- Update (`Simulation.step`): spawn (in the discs of the step's emitting spawn gates, overflowing outward where the previous step's coarse field is crowded; in the wall band, with the density bias, when no gate emits), grid count, grid scan, grid scatter, coarse field downsample, coarse field blur, density readback (every 15th step, `src/sim/density-readback.js`), steer, integrate, kill-all (count, then kill; only in the step after `requestKillAll`, or radial after `requestRadialKill`, the pickup blast: a `KillArea` uniform at binding 6 limits it to agents within a radius of the ship; a kill-all in the same step wins; kills are unscored), registered passes (`Simulation.registerPass`; `Projectiles.encode` runs projectile step, collide, rings and beam here), player contact with the hit latch (once `setPlayerState` has been called), debug kill (only while armed; only the browser checks arm it), particle step (recounts the pool's live particles), stats, stats copy into the staging ring. Every kill asks for `killBurstParticles` (12) sparks plus `killFragmentParticles` (3) heavy fragments from one per-step budget, the pool slots free after the last particle step; kill-all thins its bursts evenly when a clear would outrun it and dims them to a light budget, and in the death clear's step it first emits the death flood (a white flash and `deathFloodParticles` at the ship). The step clears the pool's per-step claims and only the stats buffer's per-frame prefix; its persistent tail (`playerHitSequence`, `hitLatch` and the cumulative scored `kills` counter) survives, and a capacity swap (`commitCapacity`, its own submission between two frames) copies it into the new simulation along with the compacted alive agents, then builds the new simulation's grid and coarse field so the next render can draw it. The projectile step counts pulse ring detonations into the prefix (`ringsThisFrame`, `lastRingX`, `lastRingY`).
- Render (`Renderer.render`): warp grid layer (with this frame's shockwave impulses), trails decay, spawn gates (`Simulation.spawnGates`), glyphs (extrapolated from the newest step, or at half simulation rate interpolated from `previousAgentsBuffer`), projectiles, pickups, particles, ship and charge ring, bloom, composite. `Game.scene()` supplies the projectiles, pickups and ship; the ship hides from death until respawn, and at game over.

## Frame order of operations

One `Game.update(deltaSeconds)` is one fixed step (full comments at the top of `src/game/game.js`):

1. Input: `input.update`; in Ready, the first gesture (fire, bomb, movement or stick) starts the run, and a start clears the arena with one kill-all. A rising bomb edge accepted by `RunState.useBomb` requests a kill-all before this step.
2. `PlayerShip.update` (Playing only); the mouse aims from the ship to the pointer unless a stick or touch aim is pushed.
3. `PickupDirector.update` (with `densityAt`: a spawn takes the lowest-density of up to 8 candidates on the placement annulus), then collection at the player into `WeaponState.collect`, before charge expiry; a rail pickup adds a rear-firing turret (`railTurrets`, up to `MAXIMUM_RAIL_TURRETS` = 12, 30 degrees apart around the rear of the aim; later pickups raise `railTier`) and leaves the armed weapon, its tier and charge alone (owner ruling R29). A collection also plays the pickup effect and, with `Game.pickupBlastRadius` above 0 (default 1.5, `setPickupBlastRadius`), calls `Simulation.requestRadialKill` at the ship and queues a 0.5 warp impulse; radius 0 skips the blast and queues the 0.15 impulse. A time warp pickup bypasses `WeaponState.collect`: it starts or extends the warp (`TimeWarp.start`), plays `pickup('timewarp')` and queues a 0.6 impulse in place of the 0.5 or 0.15 one (the blast still fires). The recovery guard's pity spawns always offer a weapon: on the time warp slot they take the next slot's weapon.
4. `WeaponState.update`: the armed weapon's spawns, then the turrets' rail spawns (`turretSpawns`, at the rail interval while firing, beside any weapon including the beam), go to `Projectiles.queueSpawn` and the beam to `setBeam` (cleared on the expiry frame, which keeps the turrets). One `weaponFire` cue per firing frame: the armed weapon's, or `'rail'` at the turret tier when only the turrets fired.
5. `Simulation.setPlayerState` (`setPlayer` only in Ready, so contact stays off until start), then the spawn director (`SpawnDirector.update`: gates open, drift and close, one wave at a time from a gate outside the safe radius and the aim lane; no waves in Ready, where every gate trickles) and spawn pressure (`SpawnPressure.update` with the latest stats, the step's sequence, so spawns still in flight are not requested twice, and the director's wave, so refills bank between waves and pour out during them; both paused while dying and respawning, when the step gets no gates) and its ramped seek scale and spawn distance (`setSeekScale`, `setSpawnDistanceFraction`; the ramp restarts on start and respawn and is retuned through `SpawnPressure.setRamp`), then the simulation step is submitted with the director's gate table (`SpawnDirector.spawnGates`). During a time warp (`TimeWarp`, started by a `timewarp` pickup) the director, spawn pressure and the simulation get the step's delta times `timeWarp.scale` while the projectile step gets the unscaled delta (`SimParams.projectileDt`); the warp timer counts real time, pausing keeps it, and death, a new run and quit to title end it.
6. Every ready stats frame (`readAllStats`, oldest first): kills (`killsSinceLastRead`, the difference of the cumulative counter) score once per stats frame and only while Playing, awards add lives and bombs, ring detonations queue a shockwave, and each new `playerHitSequence` is acknowledged and offered to `RunState.playerHit` (which drops the weapon and the turrets and resets the multiplier).
7. `RunState.update` drains actions: clear the arena (the death clear with the death flood) and projectiles, queue bomb and death shockwaves, respawn.

Watch mode (the lab; `Game.setWatch(fraction)`, `null` leaves it) keeps the phase Ready and disables the gesture start, so the Playing-only work of steps 2 to 4 and 6 (player movement, pickup collection, fire, scoring) never runs and contact stays off (`setPlayer` only); step 2 instead moves the player point to follow the pointer (or the move stick) so the swarm chases it, and step 5 runs a watch `SpawnPressure` with full seek that holds the alive target at `fraction` of capacity, with the director in continuous mode (no waves). `Game.start()` (the lab's Play) leaves watch mode too, and leaving the lab restores the state captured on entry (`captureLabState`).

While paused (`Game.pause`, from Escape, the HUD pause button, gamepad Options, blur, a hidden tab or the rotate overlay; only from Playing, Dying or Respawning), `Game.update` returns at once: no input read, no step, no stats read, no timers, so scores, lives and every sequence guard are exactly as they were and a hit in flight is handled after `resume()` by the usual rules; `state.phase` reads `paused`, a bomb or fire held through the pause needs a fresh press, and the main loop skips `audio.update` and ducks the music (`setPaused`). The title menu sets `Game.startsOnGesture = false` while it shows, so only its own start (button, arena tap, Enter, Space, face button) starts the run; `Game.quitToTitle` returns to Ready.

A capacity change (`Game.setCapacity` through `CapacitySwap`) is prepared (`Simulation.prepareCapacity`: buffers and pipelines) while the old simulation keeps stepping; commit and install then run synchronously between two updates, so play never pauses and no step is lost. A prepare that has not settled after `timeoutMilliseconds` (10000, on a monotonic clock) is ended by `CapacitySwap.expire`, which `Game.render` polls every frame: the request rejects with an Error named `CapacitySwapTimeout`, the pending flag clears so the probe and later swaps work again, and a prepare that resolves late is discarded. `settleApply` in `src/game/quality.js` applies a preset only when the swap succeeded. At half simulation rate (`Game.setSimulationRate('half')`, the `phoneLow` preset) the spawn pressure and simulation step of step 5 run every other update with both updates' delta; everything else still runs every update. `QualityController` (`src/game/quality.js`) takes frame times from `src/gpu/frame-timer.js` while Playing and applies presets between frames. After each update `main.js` hands `Game.freshStats` (the newest frame read this update, kills summed), the run phase and the multiplier to the audio hook (`IntensityTracker`: survival time, multiplier and kill rate); the game plays its cues itself through the hook's `cues` (`Game.create({ effects })`: bomb, death, pickup, expiry and `weaponFire(kind, tier)`, each an effect plus the matching music cue). Audio unlocks inside the gesture that starts the run (canvas pointerdown or touchstart, a key, or `audio.unlock()` from a button).

Event order inside the GPU step follows the pass order above: bomb kill-all or pickup blast, projectile kills, player contact. A pickup collected in the frame of charge expiry wins. A sidewinder detonates on its first kill into a half-size pulse ring (which pierces); every other projectile kind pierces. GPU events carry `frameSequence`; the CPU ignores hits that predate the current respawn.
