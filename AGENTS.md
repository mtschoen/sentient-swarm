# Agent instructions

## Global constraints (binding)

- Plain JavaScript ES modules and WGSL. No TypeScript. No runtime dependencies. Vite and Playwright are dev dependencies only.
- Shaders are loaded with `fetch(new URL('./shaders/<name>.wgsl', import.meta.url))` so the page also runs from any static server without Vite.
- Full-word identifiers (`maximum`, not `max`; `position`, not `pos`) in JavaScript. WGSL may use `vec2f` style built-in names but user identifiers follow the same rule.
- No em-dashes (U+2014) anywhere, including comments and docs.
- Every source file under about 500 lines, or carrying a one-line note at the top saying why.
- No hard-coded machine paths. No wall-clock assertions in tests; inject time.
- Mobile WebGPU limits are designed for: at most 8 storage buffers bound per shader stage; agent data interleaved in 16-byte aligned structs with no `vec3` in storage layouts; `@workgroup_size` at most 256; workgroup memory at most 16 KB; timestamp queries optional.
- Neighbor contributions are averaged, never summed. Per-agent fine-pass neighbor sampling is capped at `MAXIMUM_NEIGHBOR_SAMPLES = 32`.
- Arena is 16 by 9 world units, bounded, fully in view, letterboxed; renderer works in device pixels.
- Species count is 5. Coarse field is 64 by 36 cells with 8 float channels (5 species densities, 1 threat, 2 padding).
- Commit after every task with a message in the imperative; end commit messages with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Commands

- `npm run dev`: dev server on 127.0.0.1:5174 (strictPort).
- `npm run build`: static build into `dist/`, base taken from `PAGES_BASE` (default `/`).
- `npm test`: CPU logic tests via node:test.
- `npm run smoke`: Playwright browser smoke test.

## Pass order

Each animation frame `FrameLoop` runs zero or more fixed update steps, then one render. Each is its own queue submission.

- Update (`Simulation.step`): spawn (in the discs of the step's emitting spawn gates, overflowing outward where the previous step's coarse field is crowded; in the wall band, with the density bias, when no gate emits), grid count, grid scan, grid scatter, coarse field downsample, coarse field blur, density readback (every 15th step, `src/sim/density-readback.js`), steer, integrate, kill-all (count, then kill; only in the step after `requestKillAll`), registered passes (`Simulation.registerPass`; `Projectiles.encode` runs projectile step, collide, rings and beam here), player contact with the hit latch (once `setPlayerState` has been called), debug kill (only while armed; only the browser checks arm it), particle step (recounts the pool's live particles), stats, stats copy into the staging ring. Every kill asks for `killBurstParticles` (12) sparks plus `killFragmentParticles` (3) heavy fragments from one per-step budget, the pool slots free after the last particle step; kill-all thins its bursts evenly when a clear would outrun it and dims them to a light budget, and in the death clear's step it first emits the death flood (a white flash and `deathFloodParticles` at the ship). The step clears the pool's per-step claims and only the stats buffer's per-frame prefix; its persistent tail (`playerHitSequence`, `hitLatch` and the cumulative scored `kills` counter) survives, and a capacity swap (`commitCapacity`, its own submission between two frames) copies it into the new simulation along with the compacted alive agents, then builds the new simulation's grid and coarse field so the next render can draw it. The projectile step counts pulse ring detonations into the prefix (`ringsThisFrame`, `lastRingX`, `lastRingY`).
- Render (`Renderer.render`): warp grid layer (with this frame's shockwave impulses), trails decay, spawn gates (`Simulation.spawnGates`), glyphs (extrapolated from the newest step, or at half simulation rate interpolated from `previousAgentsBuffer`), projectiles, pickups, particles, ship and charge ring, bloom, composite. `Game.scene()` supplies the projectiles, pickups and ship; the ship hides from death until respawn, and at game over.

## Frame order of operations

One `Game.update(deltaSeconds)` is one fixed step (full comments at the top of `src/game/game.js`):

1. Input: `input.update`; in Ready, the first gesture (fire, bomb, movement or stick) starts the run, and a start clears the arena with one kill-all. A rising bomb edge accepted by `RunState.useBomb` requests a kill-all before this step.
2. `PlayerShip.update` (Playing only); the mouse aims from the ship to the pointer unless a stick or touch aim is pushed.
3. `PickupDirector.update` (with `densityAt`: a spawn takes the lowest-density of up to 8 candidates on the placement annulus), then collection at the player into `WeaponState.collect`, before charge expiry; a rail pickup adds a rear-firing turret (`railTurrets`, up to `MAXIMUM_RAIL_TURRETS` = 12, 30 degrees apart around the rear of the aim; later pickups raise `railTier`) and leaves the armed weapon, its tier and charge alone (owner ruling R29).
4. `WeaponState.update`: the armed weapon's spawns, then the turrets' rail spawns (`turretSpawns`, at the rail interval while firing, beside any weapon including the beam), go to `Projectiles.queueSpawn` and the beam to `setBeam` (cleared on the expiry frame, which keeps the turrets). One `weaponFire` cue per firing frame: the armed weapon's, or `'rail'` at the turret tier when only the turrets fired.
5. `Simulation.setPlayerState` (`setPlayer` only in Ready, so contact stays off until start), then the spawn director (`SpawnDirector.update`: gates open, drift and close, one wave at a time from a gate outside the safe radius and the aim lane; no waves in Ready, where every gate trickles) and spawn pressure (`SpawnPressure.update` with the latest stats, the step's sequence, so spawns still in flight are not requested twice, and the director's wave, so refills bank between waves and pour out during them; both paused while dying and respawning, when the step gets no gates) and its ramped seek scale and spawn distance (`setSeekScale`, `setSpawnDistanceFraction`; the ramp restarts on start and respawn and is retuned through `SpawnPressure.setRamp`), then the simulation step is submitted with the director's gate table (`SpawnDirector.spawnGates`).
6. Every ready stats frame (`readAllStats`, oldest first): kills (`killsSinceLastRead`, the difference of the cumulative counter) score once per stats frame and only while Playing, awards add lives and bombs, ring detonations queue a shockwave, and each new `playerHitSequence` is acknowledged and offered to `RunState.playerHit` (which drops the weapon and the turrets and resets the multiplier).
7. `RunState.update` drains actions: clear the arena (the death clear with the death flood) and projectiles, queue bomb and death shockwaves, respawn.

While paused (`Game.pause`, from Escape, the HUD pause button, gamepad Options, blur, a hidden tab or the rotate overlay; only from Playing, Dying or Respawning), `Game.update` returns at once: no input read, no step, no stats read, no timers, so scores, lives and every sequence guard are exactly as they were and a hit in flight is handled after `resume()` by the usual rules; `state.phase` reads `paused`, a bomb or fire held through the pause needs a fresh press, and the main loop skips `audio.update` and ducks the music (`setPaused`). The title menu sets `Game.startsOnGesture = false` while it shows, so only its own start (button, arena tap, Enter, Space, face button) starts the run; `Game.quitToTitle` returns to Ready.

A capacity change (`Game.setCapacity` through `CapacitySwap`) is prepared (`Simulation.prepareCapacity`: buffers and pipelines) while the old simulation keeps stepping; commit and install then run synchronously between two updates, so play never pauses and no step is lost. At half simulation rate (`Game.setSimulationRate('half')`, the `phoneLow` preset) the spawn pressure and simulation step of step 5 run every other update with both updates' delta; everything else still runs every update. `QualityController` (`src/game/quality.js`) takes frame times from `src/gpu/frame-timer.js` while Playing and applies presets between frames. After each update `main.js` hands `Game.freshStats` (the newest frame read this update, kills summed), the run phase and the multiplier to the audio hook (`IntensityTracker`: survival time, multiplier and kill rate); the game plays its cues itself through the hook's `cues` (`Game.create({ effects })`: bomb, death, pickup, expiry and `weaponFire(kind, tier)`, each an effect plus the matching music cue). Audio unlocks inside the gesture that starts the run (canvas pointerdown or touchstart, a key, or `audio.unlock()` from a button).

Event order inside the GPU step follows the pass order above: bomb kill-all, projectile kills, player contact. A pickup collected in the frame of charge expiry wins. Every projectile kind pierces. GPU events carry `frameSequence`; the CPU ignores hits that predate the current respawn.

- `src/input/`: `menuInput.js` (menu actions from keys and gamepad edges: arrows, d-pad, left stick, Enter, Space, faces, Escape and Options), `input.js` (unified `InputState`), `keyboard.js`, `pointer.js`, `touch.js`, `gamepad.js`.
